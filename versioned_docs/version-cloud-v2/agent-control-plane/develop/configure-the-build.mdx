# Configure the Build

The build configuration sets where an agent's source comes from, how it's built, how it receives requests, and how Kubernetes checks it. Changes apply from the next build.

## Open the build configuration

Open the agent, click **Build** under **Agent lifecycle**, then click **Configure build**. The **Configure Build** panel opens.

## Repository Details

| Field | Description |
|---|---|
| **GitHub Repository** | The repository URL. |
| **Branch** | The branch to build. |
| **Project Path** | The folder of the agent in the repository. |

## Build Details

Choose **Python**, **Ballerina**, or **Docker**. For Python, set:

| Field | Description |
|---|---|
| **Language Version** | The runtime version, for example `3.11`. |
| **Start Command** | The command that starts the agent. Dependencies are installed automatically from `package.json`, `requirements.txt`, or `pyproject.toml`. |

## Agent Interface

Choose how your agent receives requests, for example **Chat agent** (`POST /chat` on port `8000`) or **Custom API agent** (your OpenAPI specification and port).

## Health Checks

Health checks tell Kubernetes how to check the agent. Empty fields use the defaults below.

| Check | What it does | On by default | Defaults |
|---|---|---|---|
| **Startup** | Waits for the agent to start; runs until it first passes. | Yes | TCP on port 8000. Initial delay 10 s, interval 5 s, timeout 1 s, 60 failures allowed. |
| **Readiness** | Decides whether the agent receives traffic; runs for as long as it runs. | Yes | TCP on port 8000. Initial delay 0 s, interval 5 s, timeout 1 s, 6 failures allowed. |
| **Liveness** | Restarts the agent when it stops responding. | No | |

## Save the configuration

Click **Update build configuration**. To build with the new configuration, [trigger a build](./build-an-agent.mdx#trigger-a-build).
