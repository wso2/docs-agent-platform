# Monitor Gateway Metrics

The Gateway Controller and the policy engine in the Gateway Runtime expose Prometheus metrics. The gateway bundle includes Prometheus and Grafana with ready-made dashboards.

## Enable Metrics

1. Add these settings to `configs/config.toml`:

   ```toml
   [controller.metrics]
   enabled = true

   [policy_engine.metrics]
   enabled = true
   port = 9003
   ```

2. Start the gateway with the `metrics` profile. The gateway reads `config.toml` only when it starts, so recreate the containers:

   ```bash
   docker compose --profile metrics up -d --force-recreate
   ```

## View the Metrics

| Tool | Address | Sign-in |
|---|---|---|
| Grafana | `http://127.0.0.1:3000` | `admin` / `admin` |
| Prometheus | `http://localhost:9092` | None |

Grafana asks you to change the default password. Click **Skip** for a local test. Grafana opens on the **Infrastructure Overview** dashboard. The bundle also provides **Gateway Controller** and **Policy Engine** dashboards.

In Prometheus, open **Status** → **Targets** to check the scrape jobs. The `gateway-controller` and `policy-engine` jobs show **UP**. The `router` job stays **DOWN**, because the router admin interface listens only on the container's loopback address.

## Scrape the Metrics Yourself

To use your own Prometheus, scrape these endpoints:

| Component | Host port | Path |
|---|---|---|
| Gateway Controller | `9011` | `/metrics` |
| Policy engine | `9003` | `/metrics` |

Port `9011` is the host port for the controller's container port `9091`. If you changed the published ports with a `docker-compose.override.yaml`, publish these two ports again, or Prometheus on the host cannot reach them. Port `3000` is also used by many local tools. If it is taken, change the host side of the Grafana port mapping.
