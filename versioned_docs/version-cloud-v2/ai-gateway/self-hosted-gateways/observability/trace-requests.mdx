# Trace Requests

A trace follows one request through the gateway. Each step is a span. The router and the policy engine pass the trace from one to the next with the W3C `traceparent` and `tracestate` headers.

The demonstration stack is an OpenTelemetry Collector and Jaeger. The gateway sends spans to the collector on gRPC port 4317 or HTTP port 4318, and the collector forwards them to Jaeger. You can send the same spans to any OTLP backend instead.

## Enable Tracing

Add the tracing settings to `configs/config.toml`:

```toml
[tracing]
enabled = true                          # Set to true to enable tracing
endpoint = "otel-collector:4317"        # OTLP collector gRPC endpoint
insecure = true                         # Plaintext connection to the collector
service_version = "1.0.0"               # Service version
batch_timeout = "1s"                    # Batch timeout for exporting spans
max_export_batch_size = 512             # Maximum spans per batch
sampling_rate = 1.0                     # Sample rate (1.0 = 100%, 0.5 = 50%)
```

Start the gateway with the tracing services:

```bash
docker compose --profile tracing up -d
```

This starts **gateway-controller**, **gateway-runtime**, the OpenTelemetry Collector, and Jaeger.

To run the gateway without that stack:

```bash
docker compose up -d
```

:::note
If tracing is enabled and the collector is not running, the components log export warnings. Set `enabled = false` to turn tracing off. Jaeger keeps traces in memory, so stopping it drops them unless you add a storage backend.
:::

Stop the stack:

```bash
docker compose --profile tracing down
```

## View Traces in Jaeger

1. Open `http://localhost:16686`.
2. Send a request through the gateway so that a trace exists.
3. Select a service, such as `router`.
4. Optionally select an operation, or leave it as all.
5. Set the lookback (5m, 15m, 1h, 6h, 12h, 1d, 2d, or custom). The default is the last hour.
6. Optionally filter by tags (for example `http.status_code=500`), duration, or result limit. The default limit is 20.
7. Click **Find Traces**.

Open a trace to see the timeline, how long each span took, and the parent and child spans. Open a span for its operation name, duration, tags, logs, and process.

- **Slow requests:** set a minimum duration, such as 1000ms, then click **Find Traces**.
- **Errors:** filter with `error=true` or `http.status_code=500`.
- **One request:** search by the trace ID from a `traceparent` header.

Select traces and click **Compare Traces** to compare them. Click **Dependencies** to see which services called which.

## Change What Is Exported

Sample fewer requests:

```toml
[tracing]
sampling_rate = 0.1  # Sample 10% of requests
```

`1.0` samples every request. `0.5` samples half, `0.1` samples 10%, and `0.01` samples 1%. A lower rate costs less and can miss traces.

Set the service name that the router reports:

```toml
[router]
tracing_service_name = "router-prod-us-east-1"
```

Change how spans are batched:

```toml
[tracing]
batch_timeout = "5s"            # Wait up to 5s before exporting
max_export_batch_size = 1024    # Export up to 1024 spans per batch
```

A shorter timeout shows traces sooner. A longer timeout sends fewer, larger batches.

## Send Traces Somewhere Else

Keep the gateway endpoint pointed at an OTLP collector, and change the collector exporters. The collector file is `observability/otel-collector/config.yaml`.

### Moesif

```yaml
exporters:
  # Export to Moesif
  otlphttp:
    endpoint: https://api.moesif.net/v1/traces
    headers:
      X-Moesif-Application-Id: 'your-moesif-application-id'

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch, resource]
      exporters: [otlphttp]  # Send to Moesif
```

Use the `otlphttp` exporter and HTTPS. The `X-Moesif-Application-Id` header is required.

To get the application ID, sign in at [moesif.com](https://www.moesif.com), open **Settings** → **Installation** or **API Keys**, and copy the **Collector Application ID**.

To pass the ID as an environment variable:

```yaml
exporters:
  otlphttp:
    endpoint: https://api.moesif.net/v1/traces
    headers:
      X-Moesif-Application-Id: '${MOESIF_APPLICATION_ID}'
```

```yaml
otel-collector:
  image: otel/opentelemetry-collector:latest
  environment:
    - MOESIF_APPLICATION_ID=${MOESIF_APPLICATION_ID}
  # ... rest of configuration
```

```bash
export MOESIF_APPLICATION_ID=your-moesif-application-id
docker compose --profile tracing up -d
```

To send to Jaeger and Moesif together:

```yaml
exporters:
  # Local Jaeger for development
  otlp/jaeger:
    endpoint: jaeger:4317
    tls:
      insecure: true

  # Moesif for analytics
  otlphttp/moesif:
    endpoint: https://api.moesif.net/v1/traces
    headers:
      X-Moesif-Application-Id: '${MOESIF_APPLICATION_ID}'

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch, resource]
      exporters: [otlp/jaeger, otlphttp/moesif]
```

## Collector Configuration

`observability/otel-collector/config.yaml` has receivers, processors, exporters, and a pipeline that connects them.

Receive OTLP:

```yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318
```

Process spans:

```yaml
processors:
  # Batch spans for efficiency
  batch:
    timeout: 1s
    send_batch_size: 1024

  # Memory limiter to prevent out-of-memory errors
  memory_limiter:
    check_interval: 1s
    limit_mib: 512
```

Export them:

```yaml
exporters:
  # Send to Jaeger
  otlp:
    endpoint: jaeger:4317
    tls:
      insecure: true

  # Debug output to console
  debug:
    verbosity: detailed
    sampling_initial: 5
    sampling_thereafter: 200
```

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch, resource]
      exporters: [otlp, debug]
```

Send one pipeline to several backends:

```yaml
exporters:
  otlp/jaeger:
    endpoint: jaeger:4317
    tls:
      insecure: true

  otlp/tempo:
    endpoint: tempo:4317
    tls:
      insecure: true

  datadog:
    api:
      key: ${DD_API_KEY}

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [otlp/jaeger, otlp/tempo, datadog]
```

Keep error traces, slow traces, and a sample of the rest. The `tail_sampling` processor is available in the OpenTelemetry Collector Contrib distribution:

```yaml
processors:
  tail_sampling:
    policies:
      - name: error-traces
        type: status_code
        status_code:
          status_codes: [ERROR]
      - name: slow-traces
        type: latency
        latency:
          threshold_ms: 1000
      - name: probabilistic
        type: probabilistic
        probabilistic:
          sampling_percentage: 10
```

## Pass a Trace Through the Gateway

If you omit `traceparent`, the gateway starts a new trace. To continue a trace you already have, send the header with your request:

```bash
curl http://localhost:8080/<context>/<path> \
  -H "traceparent: 00-0af7651916cd43dd8448eb211c80319c-b7ad6b7169203331-01"
```

## Choose a Sampling Rate

| Traffic Volume | Sampling Rate | Use Case |
|---|---|---|
| Under 100 requests per second | 100% (1.0) | Full visibility, low overhead |
| 100 to 1,000 requests per second | 10 to 50% (0.1 to 0.5) | Balanced visibility and cost |
| 1,000 to 10,000 requests per second | 1 to 10% (0.01 to 0.1) | Cost-effective, statistical sampling |
| Over 10,000 requests per second | 0.1 to 1% (0.001 to 0.01) | Minimal overhead |

Use tail sampling if you want every error trace kept while ordinary traffic is sampled. In production, use TLS on the collector connection and a memory limit on the collector.

## Troubleshooting

### No Traces in Jaeger

1. Confirm that tracing is on. In `configs/config.toml`, `enabled` under `[tracing]` must be `true`.

   ```bash
   grep -A8 "\[tracing\]" configs/config.toml
   ```

2. Confirm that the collector and Jaeger are running:

   ```bash
   docker compose --profile tracing ps
   curl http://localhost:16686/
   ```

3. Read the collector and gateway logs:

   ```bash
   docker compose logs otel-collector
   docker compose logs gateway-runtime | grep -i trace
   docker compose logs gateway-controller | grep -i trace
   ```

4. Check that the containers can reach each other:

   ```bash
   docker compose exec gateway-runtime getent hosts otel-collector
   ```

If spans are missing, the sampling rate may be too low, a component may not be exporting, or the `traceparent` header may have been dropped. Clock skew across containers shows up as wrong span times.

### Export Uses Too Much CPU or Network

Lower the sampling rate and export larger batches less often:

```toml
[tracing]
sampling_rate = 0.1
batch_timeout = "5s"
max_export_batch_size = 2048
```

### Jaeger Does Not Open

```bash
docker compose logs jaeger
curl http://localhost:16686/
```

Port 16686 must be reachable on the host.

## Turn Tracing Off

In `configs/config.toml`:

```toml
[tracing]
enabled = false
```

Then recreate the containers:

```bash
docker compose up -d --force-recreate gateway-controller gateway-runtime
```
