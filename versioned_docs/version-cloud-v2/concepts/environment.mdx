# Environment

An Environment is an isolated space where your agents run and resources are deployed. Typical examples include development, staging, and production. Every agent deployment, gateway registration, and MCP server endpoint in Agent Control Plane is scoped to one or more environments. 

## What's Scoped Per Environment

Because agents, gateways, and proxies are all deployed per environment, most of what you configure in Agent Control Plane varies by environment rather than being set once globally:

- **Agent deployments** — a given agent version is deployed independently to each environment it's promoted to.
- **AgentID** — every environment provisions its own dedicated identity for each agent that runs in it; see [Agent ID](./agentid.mdx).
- **Gateway artifacts** — an [LLM Service Provider](./llm-service-provider.mdx) or [MCP Server](./mcp-proxy.mdx) deploys one gateway artifact per environment it's configured for, to that environment's active **[Gateway](./gateway.mdx)**.
- **Identity providers** — the token issuers each environment's gateway trusts. A token accepted in development is not automatically accepted in production. 

## Where You Manage Environments

Environments are managed in Choreo Cloud and shared by every product in your organization. To create or edit one, open the organization **Settings** from the app launcher and click **Environments**. See [Manage Environments and Deployment Pipelines](../guides/environment-management.mdx).

## Relationship to Deployment Pipelines

Environments don't stand alone — a **[Deployment Pipeline](./deployment-pipeline.mdx)** defines the order agents are allowed to move through a set of environments (for example, requiring a dev deployment before staging, and staging before production).
