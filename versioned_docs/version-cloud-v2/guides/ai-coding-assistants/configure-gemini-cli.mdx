# Configure Gemini CLI with AI Gateway

This guide explains how to configure Google Gemini CLI to send requests through Agent Control Plane using the Choreo AI Gateway and a Gemini LLM Service Provider.

By routing requests through Agent Control Plane instead of invoking Google Gemini directly, you can apply security, traffic control, and governance policies such as guardrails and rate limiting. The AI Gateway acts as an intermediary, forwarding requests from Google Gemini CLI to Google Gemini while enforcing these controls.

## Prerequisites

Before you begin, make sure you have the following:

- A Google Gemini API key.
- An Agent Control Plane account. [Sign up for free](https://console.cloud.choreolabs.com/agent-management/).
- Docker and Docker Compose, to run the self-hosted gateway.
- Google Gemini CLI installed.

## Step 1: Add an AI Gateway in Agent Control Plane

:::note
If an AI Gateway is already created and active, continue to Step 2.
:::

:::tip
For the same self-hosted gateway flow in a standalone guide, see the [Quick Start Guide](../../ai-gateway/self-hosted-gateways/quickstart-guide.mdx).
:::

If an AI Gateway is not already created, follow these steps:

1. Sign in to [the Console](https://console.cloud.choreolabs.com/agent-management/).

2. In the left navigation menu, go to **Infrastructure** → **Gateways**.

3. Click **Add gateway**.

4. Enter the following values:

    | Field | Value |
    |---|---|
    | **Display Name** | My AI Gateway |
    | **Name** | `my-ai-gateway` |
    | **Environment** | Select your environment. |
    | **Public URL** | `https://localhost:8443` |

5. Click **Create**.

6. Follow the instructions shown on the **Set up My AI Gateway** panel. In the **Docker** tab, run these steps on the machine that hosts the gateway:
    - Download and unzip the gateway package with the command that the panel shows.
    - Open the unzipped directory, and run `./scripts/setup.sh`. The script creates the listener certificate, the at-rest encryption key, and the `api-platform.env` file. It prints the admin password once, so copy it.
    - Click **Copy** next to the third step, and run the command. It appends the control plane host and your gateway token to `api-platform.env`.
    - Start the gateway with `docker compose up`.

:::warning
The Console shows the gateway token only once, when you create the gateway. Run the command in the third step before you close the panel.
:::

:::note
If a default gateway port is already in use on your machine, edit the port mappings in the `docker-compose.yaml` file before you start the gateway, and use the same host port in the **Public URL**.
:::

Once the AI Gateway is active, you can continue to create the Gemini LLM Service Provider.

## Step 2: Create and Deploy a Gemini LLM Service Provider

1. Sign in to [the Console](https://console.cloud.choreolabs.com/agent-management/).

### Create a Gemini LLM Service Provider

1. In the left navigation menu, go to **Resources** → **LLM service providers**.

2. Click **Add service provider**.

3. Under **Basic Details**, enter the following values:

    | Field | Value |
    |---|---|
    | **Name** | Gemini |
    | **Version** | v1.0 |
    | **Context path** | `/geminicli` |

4. Under **Provider Template**, select **Gemini** as the LLM Service Provider.

5. Under **Runtime Configuration**, in the **API key / Credential** field, enter your Google Gemini API key.

6. Under **Deployment Configuration**, select the environment that your gateway belongs to. Open the gateway list that appears, and select **My AI Gateway**. The list defaults to the managed gateway, so change it.

7. Click **Add provider**.

The Gemini LLM Service Provider is now deployed to the selected AI Gateway.

## Step 3: Configure the API Key Header and Create an API Key

The LLM Service Provider is the endpoint that Google Gemini CLI invokes through Agent Control Plane.

### Configure the API Key Header for Google Gemini CLI

Google Gemini CLI sends its API key in a header named `x-goog-api-key`. The LLM Service Provider must be configured to accept this header.

1. On the provider page, go to the **Security** tab.

2. Under **Authentication**, change the **Header Key** from:

    ```text
    API-Key
    ```

    to:

    ```text
    x-goog-api-key
    ```

3. Click **Save**.

### Generate an API Key for Gemini CLI

Google Gemini CLI needs an API key from Agent Control Plane to invoke the deployed LLM Service Provider.

1. On the provider page, open the **API Keys** tab.

2. Click **Create API key**.

3. Enter a **Display name** for the API key.

4. Click **Create**.

5. Copy and save the generated API key. The Console shows it only once.

    This is the key that you provide to Gemini CLI.

6. In the **Overview** tab, copy and save the **Invoke URL**.

You use these values when configuring Gemini CLI.

## Step 4: Configure Gemini CLI Environment Variables

Open a terminal session where you want to run Google Gemini CLI.

Export the Invoke URL copied from the LLM Service Provider overview page:

```bash
export GOOGLE_GEMINI_BASE_URL="<INVOKE URL>"
```

Export the API key generated in Agent Control Plane:

```bash
export GEMINI_API_KEY="<AI GATEWAY API KEY>"
```

Replace the following placeholders:

- `<INVOKE URL>` with the Invoke URL copied from the LLM Service Provider overview page.
- `<AI GATEWAY API KEY>` with the API key generated in Agent Control Plane.

:::note
Set these environment variables in the same terminal session where you run Gemini CLI. Alternatively, you can configure them as permanent environment variables.
:::

### Configure SSL Certificate Trust

When you use a local Choreo AI Gateway over HTTPS, Gemini CLI must be able to trust the certificate presented by the AI Gateway.

:::note
If the AI Gateway uses a valid CA-signed certificate, no additional certificate configuration is required.
:::

If the AI Gateway uses a self-signed certificate, Gemini CLI might fail to connect because of certificate verification errors. In such cases, extract the gateway certificate and point Node.js at it before you run the client:

1. Extract the certificate and save it as `gateway_certificate.pem` in the current directory.

   ```bash
   echo -n | openssl s_client -connect localhost:8443 2>/dev/null | sed -ne '/-BEGIN CERTIFICATE-/,/-END CERTIFICATE-/p' > gateway_certificate.pem
   ```

   If you changed the HTTPS host port of the gateway, use that port instead of `8443`.

2. Export the certificate path in the terminal where you run the client.

   ```bash
   export NODE_EXTRA_CA_CERTS="$PWD/gateway_certificate.pem"
   ```

For more information, see the [official Gemini CLI documentation](https://geminicli.com/docs/resources/troubleshooting/).

To bypass SSL certificate validation during testing, run:

```bash
export NODE_TLS_REJECT_UNAUTHORIZED=0
```

## Step 5: Run Google Gemini CLI

After you set the required environment variables, run Gemini CLI:

```bash
gemini
```

Google Gemini CLI now sends requests through Agent Control Plane instead of directly calling the Gemini API.

## Use Case Examples

### Implement Choreo AI Gateway Guardrails for Enhanced Control

Choreo AI Gateway guardrails enable granular control over the data exchanged between Gemini CLI and the Google Gemini API.

By applying guardrails, you can enforce security and compliance policies.

For example, you can configure a **PII Masking Regex Guardrail** on the provider's **Guardrails** tab to prevent Personally Identifiable Information (PII) from reaching the Google Gemini API. If a user submits a prompt containing PII, the guardrail evaluates the request against defined patterns and redacts the matches before they reach the Google Gemini API.

![Gemini CLI terminal showing a support ticket summary with credentials and phone numbers masked by the PII guardrail](../../img/guides/ai-coding-assistants/configure-gemini-cli/gemini-cli-guardrail-redacted-example.png)

For more information, see the [PII Masking Regex policy](https://wso2.com/api-platform/policy-hub/policies/pii-masking-regex) in the Policy Hub. To block prompt injection with guardrails, see [Block Prompt Injection with Guardrails](../govern-llm-traffic/block-prompt-injection-with-guardrails.mdx).

### Rate Limiting at the AI Gateway

Choreo AI Gateway supports request-based and token-based rate limiting for AI APIs. This lets you control Gemini CLI usage when requests are routed through the AI Gateway.

For example, set a consumer-level token limit on the provider's **Rate Limiting** tab. Each developer's key then gets its own quota, and the AI Gateway returns `HTTP 429` once a developer reaches it. For the steps, see [Enforce Token-Based Rate Limiting](../govern-llm-traffic/enforce-token-based-rate-limiting.mdx).

This helps control token consumption and avoid unexpected costs.

The following screenshot illustrates Gemini CLI operating under a minute-level token limit, where requests are delayed until the quota is refreshed.

![Gemini CLI terminal showing a request that the rate limit delays, with a message that the response is taking longer](../../img/guides/ai-coding-assistants/configure-gemini-cli/gemini-cli-rate-limit-example.png)

### Multi-Model Routing

Choreo AI Gateway supports multi-model routing, which lets you dynamically route requests to different AI models based on defined conditions or strategies.

This is useful when you work with Gemini CLI in scenarios such as fallback handling, load balancing, or cost optimization. Instead of sending all requests to a single model, the AI Gateway can distribute or reroute requests across multiple endpoints.

To set it up, follow these steps:

1. On the provider page, open the **Guardrails** tab.
2. Under **Global Guardrails**, click **Add guardrail**, and then select **Model Round Robin**.
3. Expand **models**, and click **Add item** for each model. Add `gemini-2.5-flash-lite` and `gemini-2.5-flash`.
4. For each item, enter the provider's own ID in **Provider**. The ID is the value after `/llm-providers/view/` in the page URL. If you leave **Provider** empty, the deployment fails.
5. Click **Add**, and then click **Save** at the bottom of the tab.

For example, the following screenshot illustrates Gemini CLI being routed through the Choreo AI Gateway, where the user explicitly requests the `gemini-3.1-pro-preview` model. Since this model has exceeded its usage limits, the request fails.

![Gemini CLI terminal showing the Usage limit reached for all Pro models error after requesting gemini-3.1-pro-preview](../../img/guides/ai-coding-assistants/configure-gemini-cli/gemini-cli-multi-model-routing-example-1.png)

With multi-model routing configured using a Round Robin strategy across `gemini-2.5-flash-lite` and `gemini-2.5-flash`, the behavior changes. Even though Gemini CLI continues to request the `gemini-3.1-pro-preview` model, the AI Gateway dynamically routes the request to one of the available configured models.

As a result, the request is successfully processed without requiring any changes on the client side.

![Gemini CLI terminal showing a successful response with an interaction summary and gemini-2.5-flash model usage statistics](../../img/guides/ai-coding-assistants/configure-gemini-cli/gemini-cli-multi-model-routing-example-2.png)

For more information, see the [Model Round Robin policy](https://wso2.com/api-platform/policy-hub/policies/model-round-robin) in the Policy Hub and [Set Up a Multi-Model LLM Service Provider](../govern-llm-traffic/set-up-a-multi-model-llm-service-provider.mdx).

### Prompt Decorator

Choreo AI Gateway supports Prompt Decorators, which let you modify or enrich prompts before the AI Gateway sends them to the backend AI provider. This is useful for enforcing consistent instructions, adding system-level context, or guiding model behavior without requiring changes in the client application.

As an example, you can configure a Prompt Decorator on the provider's **Guardrails** tab to prepend a system instruction to all incoming prompts:

```text
You are operating behind an enterprise AI gateway. Follow these rules:
1. Be concise and direct.
2. Never output secrets, tokens, or credentials.
3. When editing code, explain the change briefly.
4. When unsure, state the assumption explicitly.
5. At the end of every response, add the text: 'Routed through WSO2 AI Gateway'.
```

Once configured, the AI Gateway automatically modifies every request sent from Gemini CLI to include this instruction before forwarding it to the AI provider.

![Gemini CLI terminal showing a capabilities response ending with the Routed through WSO2 AI Gateway footer added by the Prompt Decorator](../../img/guides/ai-coding-assistants/configure-gemini-cli/gemini-cli-prompt-decorator-example.png)

For more information, see the [Prompt Decorator policy](https://wso2.com/api-platform/policy-hub/policies/prompt-decorator) in the Policy Hub and [Enforce a Consistent AI Persona](../govern-llm-traffic/enforce-a-consistent-ai-persona.mdx).
