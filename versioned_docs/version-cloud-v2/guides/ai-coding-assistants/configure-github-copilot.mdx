# Configure GitHub Copilot with AI Gateway

## Overview

GitHub Copilot uses GitHub-hosted models by default. Its bring your own key (BYOK) option lets you point GitHub Copilot at a model provider of your choice instead.

This guide shows you how to use BYOK to route GitHub Copilot requests through the Choreo AI Gateway to OpenAI. When developers connect GitHub Copilot to OpenAI directly, each developer needs the OpenAI API key, and there is no central place to control or track how GitHub Copilot is used. By the end, you have GitHub Copilot sending requests to an LLM Service Provider on the Choreo AI Gateway, where each request is authenticated with an Agent Control Plane API key and governed by the policies you attach.

The guide covers two GitHub Copilot clients:

- **GitHub Copilot CLI**, the terminal assistant.
- **GitHub Copilot in Visual Studio Code (VS Code)**, using Copilot Chat.

## Learning Objectives

- Route GitHub Copilot requests to OpenAI through an LLM Service Provider, so developers use an Agent Control Plane API key and never handle the OpenAI API key.
- Configure GitHub Copilot CLI and GitHub Copilot in VS Code to send requests to a custom endpoint using BYOK.
- Set up SSL certificate trust so GitHub Copilot can connect to an AI Gateway that uses a self-signed certificate.
- Control GitHub Copilot usage by attaching guardrail, rate limit, and prompt decorator policies to the LLM Service Provider.

## Key Concepts

This guide uses the following terms:

- *Agent Control Plane* is where you create and manage AI Gateways, LLM Service Providers, and the policies attached to them.
- *AI Gateway* is the runtime that receives requests from GitHub Copilot and enforces the policies attached to the LLM Service Provider. This guide uses a self-hosted gateway. For more information, see the [Gateway](../../concepts/gateway.mdx) concept.
- *LLM Service Provider* is a registered connection to a model provider, such as OpenAI. It stores the provider's API key, so developers do not need it, and it is where you attach policies. For more information, see the [LLM Service Provider](../../concepts/llm-service-provider.mdx) concept.
- *Policy* is a rule that the AI Gateway applies to each request, such as a guardrail, a rate limit, or a prompt decorator.
- *Bring your own key (BYOK)* is the GitHub Copilot option that sends requests to a model provider you configure instead of to GitHub-hosted models. In VS Code, a model added this way is called a custom endpoint model.

## How the Request Flow Works

When a developer selects a model configured with BYOK, GitHub Copilot sends the chat and agent requests for that model to the URL configured for the model, instead of to GitHub-hosted models. In this setup, that URL is the invoke URL of an LLM Service Provider deployed on the Choreo AI Gateway.

The following diagram shows how GitHub Copilot CLI and GitHub Copilot in VS Code send requests through an OpenAI LLM Service Provider on the Choreo AI Gateway to OpenAI:

```mermaid
flowchart LR
  A["GitHub Copilot CLI (terminal)"] -->|"Request with API-Key header"| P
  B["GitHub Copilot in VS Code"] -->|"Request with API-Key header"| P
  subgraph G["Choreo AI Gateway"]
    P["OpenAI LLM Service Provider: checks the API key, applies policies, adds the OpenAI API key"]
  end
  P -->|"Forwarded request"| O["OpenAI"]
```

1. **GitHub Copilot to the LLM Service Provider.** GitHub Copilot CLI or GitHub Copilot in VS Code sends the request to the LLM Service Provider, with the Agent Control Plane API key in the `API-Key` header.
2. **Policy enforcement.** The AI Gateway checks the API key and applies the policies attached to the LLM Service Provider, such as guardrails, rate limits, and prompt decorators.
3. **Forwarding to OpenAI.** The OpenAI LLM Service Provider adds the OpenAI API key and forwards the request to OpenAI.
4. **Response.** OpenAI streams the response back through the Choreo AI Gateway to GitHub Copilot.

This setup provides the following benefits:

- Developers never hold the OpenAI API key. The key is stored only in the OpenAI LLM Service Provider.
- Each developer or team can use a separate Agent Control Plane API key, which you can revoke without affecting others.
- You can add or change policies at the Choreo AI Gateway without changing GitHub Copilot settings.

## Prerequisites

Before you begin, make sure you have the following:

- An Agent Control Plane account. [Sign up for free](https://console.cloud.choreolabs.com/agent-management/).
- Docker and Docker Compose, to run the self-hosted gateway.
- An [OpenAI API key](https://platform.openai.com/api-keys).
- One of the following GitHub Copilot clients:
    - [GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli) installed.
    - [VS Code](https://code.visualstudio.com/) with GitHub Copilot installed.

:::note Using a GitHub Copilot Business or Enterprise plan with VS Code?
Your organization administrator must enable the **Bring Your Own Language Model Key in VS Code** policy. For more information, see the [VS Code language models documentation](https://code.visualstudio.com/docs/agent-customization/language-models).
:::

## Step 1: Start an AI Gateway in Agent Control Plane

:::note
If an AI Gateway is already created and active, continue to Step 2.
:::

:::tip
For the same self-hosted gateway flow in a standalone guide, see the [Quick Start Guide](../../ai-gateway/self-hosted-gateways/quickstart-guide.mdx).
:::

1. Sign in to [the Console](https://console.cloud.choreolabs.com/agent-management/).

2. In the left navigation panel, under **Infrastructure**, click **Gateways**.

3. Click **Add gateway**.

4. Enter the following values:

    | Field | Value |
    |---|---|
    | **Display Name** | My AI Gateway |
    | **Name** | `my-ai-gateway` |
    | **Environment** | Select your environment. |
    | **Public URL** | `https://localhost:8443` |

5. Click **Create**.

6. Follow the instructions shown on the **Set up My AI Gateway** panel to download, configure, and start the gateway. In the **Docker** tab, run these steps on the machine that hosts the gateway:
    - Download and unzip the gateway package with the command that the panel shows.
    - Open the unzipped directory, and run `./scripts/setup.sh`. The script creates the listener certificate, the at-rest encryption key, and the `api-platform.env` file. It prints the admin password once, so copy it.
    - Click **Copy** next to the third step, and run the command. It appends the control plane host and your gateway token to `api-platform.env`.
    - Start the gateway with `docker compose up`.

:::warning
The Console shows the gateway token only once, when you create the gateway. Run the command in the third step before you close the panel.
:::

:::note
If a default gateway port is already in use on your machine, edit the port mappings in the `docker-compose.yaml` file before you start the gateway, and use the same host port in the **Public URL**.
:::

Once the gateway status shows as **Active**, continue to Step 2. The following screenshot shows an active AI Gateway:

![Gateways page listing My AI Gateway as a self-hosted egress gateway with the Active status](../../img/guides/shared/gateways-list-active.png)

## Step 2: Create and Deploy an OpenAI LLM Service Provider

1. In the left navigation panel, under **Resources**, click **LLM service providers**.

2. Click **Add service provider**.

3. Under **Basic Details**, enter the following values:

    | Field | Value |
    |---|---|
    | **Name** | OpenAI Copilot |
    | **Version** | v1.0 |
    | **Context path** | `/copilot` |

    :::note
    The Console builds the provider ID from the name, so each provider in an organization needs a different name. If you already created a provider named `OpenAI`, use another name, such as `OpenAI Copilot`.
    :::

4. Under **Provider Template**, select **OpenAI** as the LLM Service Provider.

5. Under **Runtime Configuration**, in the **API key / Credential** field, enter your OpenAI API key.

6. Under **Deployment Configuration**, select the environment that your gateway belongs to. Open the gateway list that appears, and select **My AI Gateway**. The list defaults to the managed gateway, so change it.

7. Click **Add provider**.

The OpenAI LLM Service Provider is now deployed to the selected AI Gateway, as shown in the following screenshot:

![Deployment tab showing the OpenAI Copilot LLM Service Provider deployed to My AI Gateway with the Deployed status](../../img/guides/ai-coding-assistants/configure-github-copilot/openai-copilot-provider-deployed.png)

## Step 3: Create an API Key for GitHub Copilot

The LLM Service Provider is the endpoint that GitHub Copilot invokes through Agent Control Plane.

GitHub Copilot needs an API key from Agent Control Plane to invoke the deployed LLM Service Provider.

1. On the provider page, open the **API Keys** tab.

2. Click **Create API key**.

3. Enter a **Display name** for the API key.

4. Click **Create**.

5. Copy and save the generated API key. The Console shows it only once.

    You provide this API key to GitHub Copilot using the `API-Key` custom header.

6. In the **Overview** tab, copy and save the **Invoke URL**.

You use these values when configuring GitHub Copilot.

## Step 4: Configure SSL Certificate Trust

When you use a local Choreo AI Gateway over HTTPS, GitHub Copilot must be able to trust the certificate presented by the AI Gateway.

If the AI Gateway uses a certificate signed by a trusted certificate authority (CA), skip this step.

If the AI Gateway uses a self-signed certificate, add the gateway certificate to your operating system's trust store. GitHub Copilot CLI and VS Code both use this trust store by default.

1. Extract the gateway certificate and save it as `gateway_certificate.pem` in the current directory.

    ```bash
    echo -n | openssl s_client -connect localhost:8443 2>/dev/null | sed -ne '/-BEGIN CERTIFICATE-/,/-END CERTIFICATE-/p' > gateway_certificate.pem
    ```

    On Windows, run this command in Git Bash.

2. Add the certificate to your operating system's trust store.

    <Tabs>
      <TabItem value="macos" label="macOS" default>

    ```bash
    security add-trusted-cert -r trustRoot -k ~/Library/Keychains/login.keychain-db gateway_certificate.pem
    ```

      </TabItem>
      <TabItem value="linux" label="Linux (Ubuntu or Debian)">

    ```bash
    sudo cp gateway_certificate.pem /usr/local/share/ca-certificates/gateway_certificate.crt
    sudo update-ca-certificates
    ```

      </TabItem>
      <TabItem value="windows" label="Windows (PowerShell)">

    ```powershell
    certutil -user -addstore Root gateway_certificate.pem
    ```

      </TabItem>
    </Tabs>

3. Restart VS Code if it is open, and open a new terminal window before you run GitHub Copilot CLI.

:::note Errors Without This Step
Without the certificate in the trust store, VS Code reports `net::ERR_CERT_AUTHORITY_INVALID`, and GitHub Copilot CLI reports `The certificate was not trusted` or `The validity period in the certificate exceeds the maximum allowed`. Setting `NODE_EXTRA_CA_CERTS` does not fix the GitHub Copilot CLI error.
:::

For more information about VS Code, see the [VS Code network connections documentation](https://code.visualstudio.com/docs/setup/network).

:::note Local testing only
For local testing only, you can use the gateway's HTTP endpoint instead of the Invoke URL, for example `http://localhost:8080/<PROVIDER CONTEXT PATH>`. Do not use HTTP in production, because the API key and prompts are sent unencrypted.
:::

## Step 5: Connect GitHub Copilot to the LLM Service Provider

Follow the option for the GitHub Copilot client you use.

### Option 1: GitHub Copilot CLI

GitHub Copilot CLI reads its model provider settings from environment variables.

#### Configure Environment Variables

Open a terminal session where you want to run GitHub Copilot CLI.

Run the following commands, replacing the placeholders with your values:

```bash
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="<INVOKE URL>"
export COPILOT_PROVIDER_HEADERS="API-Key: <AI GATEWAY API KEY>"
export COPILOT_MODEL="gpt-4.1"
```

Replace the placeholders as follows:

- `<INVOKE URL>` with the Invoke URL copied from the LLM Service Provider overview page.
- `<AI GATEWAY API KEY>` with the API key generated in Agent Control Plane for the LLM Service Provider.

:::note
`COPILOT_MODEL` must be a model that the LLM Service Provider supports, such as `gpt-4.1` for OpenAI. GitHub Copilot CLI also requires the model to support tool calling and streaming. For more information, see [GitHub Copilot CLI's official documentation](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models).
:::

:::note
These environment variables apply only to the current terminal session. To make the configuration permanent, add them to your shell profile, such as `~/.zshrc` or `~/.bashrc`.
:::

#### Run GitHub Copilot CLI

After you set the required environment variables, run GitHub Copilot CLI:

```bash
copilot
```

GitHub Copilot CLI sends requests through Agent Control Plane instead of directly calling OpenAI.

### Option 2: GitHub Copilot in VS Code

Copilot Chat in VS Code connects to the LLM Service Provider as a custom endpoint model.

#### Add the LLM Service Provider as a Custom Endpoint

1. In VS Code, open the **Chat** view.

2. Open the model picker and click **Manage Language Models**.

    You can also run **Chat: Manage Language Models** from the Command Palette.

3. Click **Add Models**, and then select **Custom Endpoint**.

4. Enter a group name for the models. For example, `Choreo AI Gateway`.

5. Enter a display name, and enter the API key generated in Agent Control Plane for the LLM Service Provider.

6. Select **Chat Completions** as the API type.

    VS Code opens the `chatLanguageModels.json` file.

7. In `chatLanguageModels.json`, fill in the empty `id`, `name`, and `url` fields of the model entry, and add a `requestHeaders` field. Keep the other values that VS Code generated.

    ```json
    {
      "id": "gpt-4.1",
      "name": "GPT-4.1 (Choreo AI Gateway)",
      "url": "<INVOKE URL>/chat/completions",
      "toolCalling": true,
      "vision": true,
      "maxInputTokens": 128000,
      "maxOutputTokens": 16000,
      "requestHeaders": {
        "API-Key": "${apiKey}"
      }
    }
    ```

    Replace `<INVOKE URL>` with the Invoke URL copied from the LLM Service Provider overview page. The `requestHeaders` field sends the Agent Control Plane API key using the `API-Key` custom header.

8. Save the file.

#### Use Copilot Chat with the LLM Service Provider

1. Open the **Chat** view in VS Code.

2. In the model picker, under **Other Models**, select **GPT-4.1 (Choreo AI Gateway)**.

3. Send a prompt.

Copilot Chat sends requests through Agent Control Plane instead of directly calling OpenAI.

:::note
The Choreo AI Gateway governs the GitHub Copilot requests that use the model you configure in this guide. Other GitHub Copilot features continue to use GitHub's services. GitHub controls the bring your own key (BYOK) options in GitHub Copilot, and they might change. For the latest information, see the [GitHub Copilot CLI documentation](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models) and the [VS Code language models documentation](https://code.visualstudio.com/docs/agent-customization/language-models).
:::

## Use Case Examples

### Apply Guardrails

Choreo AI Gateway guardrails enable granular control over the data exchanged between GitHub Copilot and the OpenAI API.

By applying guardrails, you can enforce security and compliance policies such as the following:

- Input validation to ensure prompt integrity.
- Output filtering to prevent leakage of sensitive data.
- Rate limiting to control API usage and avoid cost overruns.

For example, you can configure a **PII Masking Regex Guardrail** on the provider's **Guardrails** tab to prevent Personally Identifiable Information (PII) from reaching the OpenAI API. If a user submits a prompt containing PII, the guardrail evaluates the request against defined patterns and redacts the matches before they reach the OpenAI API.

The following screenshot shows Copilot Chat in VS Code responding to a prompt that contains an email address and a phone number, with the PII Masking Regex Guardrail configured to redact PII:

![Copilot Chat in VS Code showing the email address and phone number replaced with asterisks after the PII masking guardrail redacts them](../../img/guides/ai-coding-assistants/configure-github-copilot/guardrail-pii-redacted.png)

For more information, see the [PII Masking Regex policy](https://wso2.com/api-platform/policy-hub/policies/pii-masking-regex) in the Policy Hub and [Block Prompt Injection with Guardrails](../govern-llm-traffic/block-prompt-injection-with-guardrails.mdx).

### Limit Request Rates

Choreo AI Gateway supports request-based and token-based rate limiting for AI APIs. This lets you control GitHub Copilot usage when requests are routed through the AI Gateway.

For example, set a consumer-level token limit on the provider's **Rate Limiting** tab. Each developer's key then gets its own quota, and the AI Gateway returns `HTTP 429` once a developer reaches it. For the steps, see [Enforce Token-Based Rate Limiting](../govern-llm-traffic/enforce-token-based-rate-limiting.mdx).

This helps control token consumption and avoid unexpected costs.

The following screenshot shows GitHub Copilot CLI receiving a rate limit response after the configured limit is reached:

![GitHub Copilot CLI showing a 429 rate limit exceeded message after the rate limit is reached](../../img/guides/ai-coding-assistants/configure-github-copilot/rate-limit-exceeded.png)

### Add Instructions with a Prompt Decorator

Choreo AI Gateway supports Prompt Decorators, which let you modify or enrich prompts before the AI Gateway sends them to the backend AI provider. This is useful for enforcing consistent instructions, adding system-level context, or guiding model behavior without requiring changes in the client application.

For example, you can configure a Prompt Decorator on the provider's **Guardrails** tab to append an instruction to every prompt.

The following screenshot shows Copilot Chat in VS Code responding to the same prompt twice. The first response is without a Prompt Decorator. The second response is with a Prompt Decorator configured to append the following decoration: "Answer in one short sentence."

![Copilot Chat in VS Code showing a long bulleted response without the Prompt Decorator and a one-sentence response after the Prompt Decorator is applied](../../img/guides/ai-coding-assistants/configure-github-copilot/prompt-decorator-before-after.png)

For more information, see the [Prompt Decorator policy](https://wso2.com/api-platform/policy-hub/policies/prompt-decorator) and [Enforce a Consistent AI Persona](../govern-llm-traffic/enforce-a-consistent-ai-persona.mdx).
