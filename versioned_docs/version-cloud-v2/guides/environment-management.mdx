# Manage Environments and Deployment Pipelines

Environments and deployment pipelines control *where* your agents run and *how* they move from one stage to the next, for example `development → production`.

- An **environment** is a runtime context, such as `development`, `staging`, or `production`, where agents are deployed and run.
- A **deployment pipeline** is an ordered promotion path across those environments.
- Each **project** uses one deployment pipeline, and the agents in that project are **promoted** along its path.

Environments and deployment pipelines belong to your Choreo Cloud organization and are shared by every product in it. The environments you create there are the ones Agent Control Plane deploys agents to.

## Where Each Task Happens

| Task | Where |
|---|---|
| Create and edit environments | Choreo Cloud organization **Settings** → **Environments** |
| Create, edit, and delete deployment pipelines | Choreo Cloud organization **Settings** → **Deployment Pipelines** |
| Choose a project's deployment pipeline | The project's **Settings** |
| Promote an agent to the next environment | The agent's **Deploy** page in Agent Control Plane |

## Prerequisites

- A role that can manage environments and deployment pipelines, such as **Admin** or **Platform Engineer**. See [Access Control](../concepts/organization.mdx#access-control).

---

## Open the Organization Settings

1. Sign in to the Choreo Cloud Console.
2. Click the app launcher (the grid of dots at the top left), then click **Settings**.

Environments and deployment pipelines are under **INFRASTRUCTURE** in the settings sidebar.

---

## Manage Environments

### View Environments

In the settings sidebar, click **Environments**. The page lists every environment with its name, description, type (**Critical** or **Non-critical**), status, and creation time. The organization's default environment is marked **Default**.

### Create an Environment

1. On the Environments page, click **Create Environment**.
2. Fill in the environment details.

   | Field | Description | Example |
   |---|---|---|
   | **Name** *(required)* | The environment's identifier. It can't be changed after the environment is created. | `staging` |
   | **Display name** *(required)* | The name shown throughout the Console. | `Staging` |
   | **Description** | An optional description. | `Pre-production testing` |
   | **Critical environment** | Turn this on for an environment that runs production-grade deployments. Deploying an agent to a critical environment requires a [separate permission](../concepts/deployment-pipeline.mdx#how-it-governs-promotion). | — |

3. Click **Create**.

Agent Control Plane provisions the environment and installs its API Platform Gateway for you. The new environment appears in the list.

:::note
The environment also gets its own identity service, which issues [AgentID](../concepts/agentid.mdx) credentials to every agent deployed there. Choreo provisions and operates it, so there is nothing to install or configure.
:::

### Edit an Environment

1. On the Environments page, click the edit icon on the environment's row.
2. Change the **Display name**, **Description**, or **Critical environment** setting. The **Name** can't be changed.
3. Click **Save**.

### Access the Environment's ThunderID Console

Each environment has its own ThunderID instance, which issues [AgentID](../concepts/agentid.mdx) credentials to every agent deployed in it. A few tasks are done in its console rather than in Agent Control Plane, such as creating an OAuth application for an externally-hosted agent, or looking up an agent's application by name.

Choreo provisions and operates the instance. Its console URL and administrator credentials are issued to your organization along with the environment; ask your Choreo administrator if you do not have them.

Day-to-day AgentID work, such as provisioning, viewing, rotating, and revoking a credential, is done in Agent Control Plane instead, as described in [AgentID](../concepts/agentid.mdx). You should rarely need this console.

## Manage Deployment Pipelines

### View Deployment Pipelines

In the settings sidebar, click **Deployment Pipelines**. Each pipeline shows its promotion flow, the number of projects that use it, and whether it is the organization's **Default** pipeline.

### Create a Deployment Pipeline

1. On the Deployment Pipelines page, click **Create Pipeline**.
2. Enter a **Name**. Use lowercase letters, numbers, and hyphens. The name can't be changed later.
3. Under **Promotion flow**, click **Add Environment** and add environments in the order agents should be promoted through them. Add at least one.
4. Click **Create**.

### View a Pipeline's Details

On the Deployment Pipelines page, click a pipeline. Its details page shows the number of environments, the projects that use it, its creation time, and its **Promotion flow**. Under **Projects**, click **Show projects** to list the projects that use the pipeline.

### Edit a Deployment Pipeline

1. On the Deployment Pipelines page, click the edit icon on the pipeline, or click **Edit** on its details page.
2. Under **Promotion flow**, add environments or remove one with its **×**. The pipeline's name can't be changed.
3. Click **Save Changes**.

Changing the promotion flow changes the path available to every agent in every project that uses the pipeline.

### Delete a Deployment Pipeline

1. On the Deployment Pipelines page, click the delete icon on the pipeline, or click **Delete** on its details page.
2. Confirm in the dialog.

:::note
You can't delete the organization's **Default** pipeline. Before deleting any other pipeline, check **Projects** on its details page and move those projects to a different pipeline. See [Change a Project's Deployment Pipeline](#change-a-projects-deployment-pipeline).
:::

## Change a Project's Deployment Pipeline

Every project uses one deployment pipeline. You choose it in the project's settings, not in the organization settings.

1. In the Choreo Cloud Console, open the project. Its **Overview** page shows the current pipeline under **Deployment pipeline**.
2. Click **Settings**.
3. Open the **Deployment pipeline** dropdown. Each option shows the pipeline name and its promotion flow, and the organization's default pipeline is marked **Default**.
4. Select the pipeline you want and click **Save changes**.

A project must always have a deployment pipeline. Changing it changes the promotion path for every agent in the project.

## Promote an Agent

Promoting an agent deploys the same build from one environment to the next environment in the project's deployment pipeline.

1. In the Choreo Cloud Console, open the project and click the agent under **All artifacts**. The agent opens in Agent Control Plane.
2. In the left navigation, under **Agent lifecycle**, click **Deploy**. The page shows a **Setup** card with the selected build, followed by a card for each environment in the pipeline.
3. On the card of the environment to promote from, click **Promote**.

   > **Promote** appears only when the agent is deployed in that environment and the environment has a next environment in the pipeline.

4. In the **Promote from** drawer, set up the target environment under **Configuration**:
   - Turn on **Use config from source environment** to reuse the source environment's environment variables and file mounts.
   - Or leave it off and set the target's own **Environment Variables** and **File Mounts**. Click **Add** to add one, or **Upload .env file** to add environment variables from a file.
   - Choose the **AMP Instrumentation Version** for the target environment.

   If the source environment has more than one next environment, also select the target environment.

5. Click **Promote**.

The target environment's card then shows the deployment. Repeat from that card to move the agent further along the pipeline.

Promoting to a critical environment needs the production permission. See [How It Governs Promotion](../concepts/deployment-pipeline.mdx#how-it-governs-promotion).
