# Install with a WSO2 Subscription

WSO2 Agent Manager 2026.11.0 is a short-term support (STS) release, available only with a WSO2 subscription or an evaluation of one. WSO2 publishes its Helm charts and images to `registry.wso2.com`, signs them, and follows the release with updates that carry fixes. You install it with the [k3d](./on-k3d.mdx) or [On Your Environment](./on-your-environment.mdx) guide, using the changes on this page.

## Get Your Registry Credentials

How you get registry credentials, and which registry project they open, depends on how you obtained Agent Manager.

### Evaluation

When you download Agent Manager from the WSO2 website for evaluation, WSO2 emails you registry credentials: a username and a token. Your registry project is `wso2-agent-manager-evaluations`.

### Subscription

With a WSO2 subscription, get your registry credentials from the WSO2 Customer Portal, under **Settings** → **Registry Tokens**. See [Registry Token Management](https://updates.docs.wso2.com/en/latest/updates/registry-token-management/) for how to create and manage them. Your registry project is `wso2-agent-manager`.

The rest of this page writes the registry project as `<project>`, and calls the username and token your registry credentials.

## What Changes From the Community Install

STS releases sit under `sts/` in your registry project, apart from the long-term support releases at the root of the project.

| | Community | WSO2 subscription (2026.11.0) |
|---|---|---|
| Helm charts | `oci://ghcr.io/wso2/<chart>` | `oci://registry.wso2.com/<project>/sts/helm-charts/<chart>` |
| Agent Manager images | `ghcr.io/wso2/<image>` | `registry.wso2.com/<project>/sts/<image>` |
| API Platform gateway chart and images | `ghcr.io/wso2/api-platform/...` | `registry.wso2.com/<project>/sts/helm-charts/gateway`, `registry.wso2.com/<project>/sts/gateway-controller`, and `registry.wso2.com/<project>/sts/gateway-runtime`, version `2026.10.0` |
| Chart version | Not published | `2026.11.0` for the release, `2026.11.0-u<N>` for update N |
| Image tag | Not published | `2026.11.0` for the release, `2026.11.0.<N>` for update N |
| Credentials | None | Registry username and token |

The charts in your project already point at the images in the same project, and they reference an image pull secret named `wso2-registry-credentials`. The `helm install` commands in the guides therefore stay the same. The API Platform gateway is pulled with a second pull secret, `wso2-gateway-registry-credentials`, which the gateway operator also reads to pull the gateway chart. The instrumentation image (`amp-python-instrumentation-provider`) and third-party images, such as OpenChoreo, ThunderID, and cert-manager, still come from their public registries.

WSO2 publishes the 2026.11.0 release to your project, followed by updates to it. The release is version `2026.11.0`, and update N is version `2026.11.0-u<N>`. For example, update 2 is `2026.11.0-u2`, with chart version `2026.11.0-u2` and image tag `2026.11.0.2`. This page calls either one your version. Install the newest version published to your project, unless WSO2 asks you to install a particular one.

:::note Always name the version
Helm treats an update such as `2026.11.0-u2` as a pre-release of `2026.11.0`, so it ranks every update below the release. `helm install` and `helm upgrade` without `--version`, and version ranges in tools such as Argo CD or Flux, therefore resolve to `2026.11.0` and never to an update. Pass the exact version every time.
:::

## List the Published Versions

To see which versions are published to your project, list the tags of the `wso2-agent-manager` chart with [ORAS](https://oras.land/). Helm cannot list the versions of a chart in an OCI registry, and `helm list` shows only the version installed in your cluster.

```bash
oras login registry.wso2.com
oras repo tags registry.wso2.com/<project>/sts/helm-charts/wso2-agent-manager | grep -v '\.sig$' | sort -V
```

`oras login` asks for your registry username and token. Run `oras logout registry.wso2.com` when you are done, so the login is not kept on your machine.

Without ORAS installed, run the same commands in a temporary container. Nothing is kept after it exits:

```bash
docker run --rm -it --entrypoint sh ghcr.io/oras-project/oras:v1.2.3 -c 'oras login registry.wso2.com && oras repo tags registry.wso2.com/<project>/sts/helm-charts/wso2-agent-manager | grep -v "\.sig$" | sort -V'
```

The list starts with the release, `2026.11.0`, followed by its updates in order, so the last version is the newest. The `.sig` tags that `grep` removes are the signatures described in [Verify Image Signatures](#verify-image-signatures-optional).

## Install on k3d

### One Command

Run the subscription installer with your project. It installs the newest version published to your project:

```bash
curl -fsSL https://github.com/wso2/agent-manager/releases/download/amp/v2026.11.0/k3d-install-subscription.sh | bash -s -- --project <project>
```

To install a particular version, such as one WSO2 asked you to use, add `--version`:

```bash
curl -fsSL https://github.com/wso2/agent-manager/releases/download/amp/v2026.11.0/k3d-install-subscription.sh | bash -s -- --project <project> --version 2026.11.0-u2
```

The script asks for your registry username and token, and reads the token without echoing it. It then:

1. Checks the same prerequisites as the [community one-command install](./on-k3d.mdx#install).
2. Signs in to `registry.wso2.com` with your credentials and finds your version: the one you named, or the newest published to your project.
3. Downloads the 2026.11.0 release bundle from GitHub into `~/.wso2-agent-manager/subscription/<project>/<image tag>/`. The bundle holds only the installer scripts and configuration; it contains no charts or images.
4. Creates the `amp-local` cluster and installs Agent Manager, pulling every chart, Agent Manager image, and the API Platform gateway from `registry.wso2.com/<project>/sts/`.

| Option | Description |
|---|---|
| `--project` | `wso2-agent-manager` or `wso2-agent-manager-evaluations`. Without it, the script asks which one. |
| `--version` | Install this version, such as `2026.11.0` or `2026.11.0-u2`, instead of the newest. This installer only installs 2026.11.0 and its updates, and refuses a version of another release. |
| `--download-only` | Check the credentials, find the version, download the release bundle, print its location, and stop without installing. It also shows when a newer version is published to your project. |

To run the script without prompts, set the credentials first, as described in [Provide the Credentials Without Prompts](#provide-the-credentials-without-prompts).

When the install finishes, it prints the Console URL, the admin sign-in, and the version it installed. Continue with [Verify and Access the Platform](./on-k3d.mdx#verify-and-access-the-platform).

## Add an Environment

Each environment you add gets its own API Platform gateway, which also comes from your project. Run `add-environment.sh` from the extracted release bundle, with the registry settings and your credentials, instead of the command the Console generates. The script needs `lib-registry-auth.sh`, which sits next to it in the bundle, to create the pull secrets in the new environment's namespaces.

On k3d, the one-command install extracted the bundle to `~/.wso2-agent-manager/subscription/<project>/<image tag>/`. In the On Your Environment guide, it is `${AMP_DIST}`. Start from the command the Console's **Create Environment** drawer generates, keep its variables, and add the registry settings:

```bash
helm registry login registry.wso2.com
AMP_IMAGE_REGISTRY=registry.wso2.com/<project>/sts \
GATEWAY_REGISTRY=registry.wso2.com/<project>/sts \
CHART_REF=oci://registry.wso2.com/<project>/sts/helm-charts/wso2-amp-api-platform-gateway-extension \
CHART_VERSION=<version> \
AMP_REGISTRY_CREDENTIALS_FILE=~/amp-registry.creds \
ENV_NAME=<env-name> \
DISPLAY_NAME="<display-name>" \
AGENT_MANAGER_TOKEN=<token> \
AGENT_MANAGER_URL=<agent-manager-url> \
  bash <bundle>/deployments/scripts/add-environment.sh   # plus any other variables from the Console's command
```

Use your version for `CHART_VERSION`: the Console's command names the release, `2026.11.0`, even after you upgrade to an update. `AMP_REGISTRY_CREDENTIALS_FILE` is the credentials file from [Provide the Credentials Without Prompts](#provide-the-credentials-without-prompts). Without it, the script asks for your registry username and token. Set `GATEWAY_REGISTRY` even on the `wso2-agent-manager` project: when it is unset, the gateway always comes from `wso2-agent-manager`, which an evaluation's credentials cannot read.

## Provide the Credentials Without Prompts

`k3d-install-subscription.sh` reads the credentials from `AMP_REGISTRY_USERNAME` and `AMP_REGISTRY_PASSWORD`, or from a file named by `AMP_REGISTRY_CREDENTIALS_FILE`. Keep them in a file that only you can read rather than on a command line, where they end up in your shell history:

```bash
cat > ~/amp-registry.creds <<'EOF'
AMP_REGISTRY_USERNAME='<username>'
AMP_REGISTRY_PASSWORD=<token>
EOF
chmod 600 ~/amp-registry.creds
```

Keep the single quotes around the username. A registry username can contain `$`, which a shell would otherwise expand.

```bash
curl -fsSL https://github.com/wso2/agent-manager/releases/download/amp/v2026.11.0/k3d-install-subscription.sh | AMP_REGISTRY_CREDENTIALS_FILE=~/amp-registry.creds bash -s -- --project <project>
```

## Verify the Installation

Check that the Agent Manager pods run images from your project:

```bash
kubectl get pods -n wso2-amp -o jsonpath='{range .items[*]}{.spec.containers[*].image}{"\n"}{end}' | grep amp-
kubectl get pods -n openchoreo-observability-plane -o jsonpath='{range .items[*]}{.spec.containers[*].image}{"\n"}{end}' | grep amp-
```

Each image should start with `registry.wso2.com/<project>/sts/`. The instrumentation image that platform-hosted agents use stays on `ghcr.io/wso2`, which is expected.

Check that the gateway runs the `2026.10.0` images from your project:

```bash
kubectl get pods -n openchoreo-data-plane -o jsonpath='{range .items[*]}{.spec.containers[*].image}{"\n"}{end}' | grep gateway-
```

To see which version is installed, check the chart version of the `amp` release:

```bash
helm list -n wso2-amp
```

## Troubleshooting

### Helm Fails With 401 Unauthorized

Helm is not signed in to `registry.wso2.com`. Run the `helm registry login` command from the **WSO2 Subscription** tab again, and check your [registry credentials](#get-your-registry-credentials).

### Agent Manager Pods Stay in ImagePullBackOff

Check the pod's events with `kubectl describe pod`. The usual causes are:

- The `wso2-registry-credentials` secret is missing from that pod's namespace.
- The secret was created for a registry host other than `registry.wso2.com`.
- The username was not quoted when the secret or credentials file was created, so the shell expanded its `$`.

### Gateway Pods Stay in ImagePullBackOff, or the Gateway Never Installs

The gateway pulls with `wso2-gateway-registry-credentials`, not `wso2-registry-credentials`. Check that the secret exists in `openchoreo-data-plane` and in the namespace of each environment you added, and that it carries `username` and `password` keys as well as `.dockerconfigjson`: the gateway operator reads the plain keys to pull the gateway chart. On an evaluation, also check that `GATEWAY_REGISTRY` named `wso2-agent-manager-evaluations`.
